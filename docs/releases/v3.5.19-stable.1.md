# BehaviorGate v3.5.19 · 稳定候选 stable.1

**这是一份候选版本，不是正式稳定版。** 版本号仍为 `3.5.19`；`v3.5.19` 与 `v3.5.19-notes.1` 两个历史发行保持不动。

本轮只处理五个已核实的根因，不新增产品功能。目标是让 G3 的判断链可解释、可回归，而不是继续为单个例句加分支。

## 五个根因与修法

### 1. 否定作用域

`_claim_units()` 现在复用 `_drop_negated_claims()` 的子句边界与否定判据：

- 同一句多个完成词逐个判断，不因第一个命中决定整句去留；
- 「没有异常，上传已修复」中的否定被逗号隔断，不影响后一子句；
- 「尚未修复」「如果修复完成」「和已验证的结论冲突」不再成为当前成功声明；
- 复现词同样过否定（「没有复现」不是复现声明）。

### 2. 同事项跨句关联

结论与观测可以分句、换行书写，归属线索是明确的结构信号：

- 「上传已完成。它的退出码是 0。」→ 回指，合并为同一事项；
- 「上传已完成。
退出码：0。」→ 同段（单换行）+ 证据标签，合并；
- 「上传已完成。

退出码：0。」→ 空行分段，不自动合并；
- 复用同一对象名（≥4 字符标识符，排除 exit/code/http 等观测词）也算依据；
- 不同对象共享同一状态码时不判归属（`shared-observable` 记未确认）；
- 含新声明的句子永远独立成项，不会降格为补充证据。

### 3. 复现与成功分类

每个事项单独判定为 `success` / `repro` / `unconfirmed`，汇总保留类型：

- 纯复现 → `repro`，记 `verified_by_expected_failure`，不记普通成功验证；
- 复现有依据、成功无依据 → `partial`（`units_repro=1, units_success=0`）；
- 两类事项分别有依据 → `matched`，事件分别记录 `units_success` / `units_repro`；
- 同句复现+成功无法拆分 → 未确认。

### 4. 截断优先级

`_backing_state()` 在匹配之前检查 `truncated`：

- 截断时一律 `truncated`（未确认），即使发现匹配也不记已验证；
- 已发现的观测写入事件作诊断信息；
- 证据块与行内路径都走同一函数，不再「先接受匹配、后检查截断」；
- 完整扫描无结果仍按既有逻辑打回；可见范围无结果记未确认。

### 5. heredoc 文档豁免

命令边界改为引号感知切分（`_split_command_segments()`），并取最后一个命令作为正文接收者：

- `cat > notes.md <<'EOF'`、`mkdir && cat > notes.md <<'EOF'` 保持豁免；
- `cat | sh <<'EOF'`、`sh <<'EOF' | cat`、`sh -s 'label; cat' <<'EOF'` 不获豁免；
- 引号未闭合 / 解析失败 → 取消豁免，继续走原危险规则检查；
- 取消豁免不等于直接拒绝，警告与阻断边界不变。

## 受控宿主验证（隔离项目）

在 `_host_test_project` 做项目级安装后，用 `claude -p` 做了两次真实调用：

1. 普通消息（「请只回复两个字：收到」）→ `UserPromptSubmit` 触发，`Stop` 放行且无任何 G3 事件（普通收尾安静）。
2. 宣布完成但无证据（「只回复四个字：已完成。」）→ G3 连续两次 `stop_feedback`（`missing_effect_evidence`），模型把回复改成「**证据**：未验证（NOT_MEASURED）」，第三次放行。`num_turns=3`。
3. 部分有依据（运行 `echo hi`、写证据块、声明「HTTP 200 验证通过」）→ `claim_observation_not_matched` / `allow_unconfirmed`，宿主让模型继续一轮（`num_turns=2`），但模型未明显改口。

这证明：**打回路径的 reason 能回到模型并促使改口**；`additionalContext` 路径确实被触发且宿主继续了对话，但**是否被模型理解并采纳仍未确认**。未做真实业务项目的误拦漏判统计。

## 已知边界

- 同一句内多个成功声明仍共用一个证据，未逐项核对。
- 复杂 heredoc 结构（函数包装、重定向组合）尚未全面确认。
- 相同错误码 / 退出码只证明字面一致，不证明对象、操作、问题相同。
- 扫描有界（512 KB / 800 行 / 40 条结果）；长会话常处于截断状态，因此 G3 多数情况下给出「未确认」而不是「已验证」——这是设计取舍，不是故障。
- 宿主验证只覆盖三个受控场景；真实业务中的误拦漏判、性能和长期稳定性未验证。

## 升级与回滚

- 本候选版**未覆盖当前全局安装**；安装前请先备份 `~/.claude` 下的 hooks、`behavior-policy.json`、`settings.json`、`DEPLOY_MANIFEST.json`。
- 回滚：把备份目录里的 hooks 与三个配置文件复制回去即可；`settings.json` 的挂载关系本版未改动。
