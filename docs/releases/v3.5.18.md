# BehaviorGate v3.5.18

**本版重点：修正统计口径的 REVIEW 污染、为 G3 打回补充「反复被打回」指引、收窄 G5 的变量名误拦。**

BehaviorGate 是 Claude Code 的开发行为约束插件，提供子代理预算、完成声明检查、危险模式检查及询问与测试约束。v3.5.18 内容为 v3.5.17 及其全部同版内修补；它不是安全边界，也不承诺替代代码与业务验收。

- `SHA256SUMS.txt`：发行资产的 SHA-256 校验和。

## 修复

### 统计口径：REVIEW 评审调用不再计入重复触发

`gate_stats.py` 的「重复触发」把 REVIEW 评审的每次调用（如 `review_allow`）也算了进来 —— 同一会话提交 30 次 prompt 就会在榜单上呈现为「门反复拦截」。默认口径改为只统计真实门出手（`deny` / `stop_feedback` / `stop_feedback_retry`）并排除评审事件；未知 decision 类型显式告警；旧混合口径仅保留为显式 `--json --legacy-metrics` 对照。

同一份真实数据（2,277 条）：重复触发榜从 126 组收窄到 40 组，被剔除的 86 组全部是评审污染；保留组的计数逐一不变。

### G3 打回文案：反复被打回时的指引

G3 的「证据不足」打回此前只给出「补证据后重新收尾」 —— 而真实数据里「补了又被拒」的循环存在（21 次重试仍不合规记录，跨 18 个会话）。两个证据不足分支的拒绝文案各补一行条件式指引：若因同一原因反复被打回，先说明卡点、换一种验证思路，或把选择交回用户。文案不依赖计数，不改变判定、规则 ID 与事件记录。

### G5 变量名边界：`$TMPD` 等不再误拦

`rm_rf_windows_env` 对变量名做前缀匹配且无边界 —— `$TMPD`、`$TMP_DIR`、`$HOMED`、`$env:TEMPFOO` 这些【不同变量】会被当成删除临时目录/用户目录误拦。现在变量名后要求非标识符字符才能命中；`$TMP`、`$TMP/cache`、`${TMP}`、`%TEMP%` 等真目标的拦截不变。

## 改进

### 登记核验与测试覆盖

- 核验「`rm_rf_in_content` 多行覆盖未修」的旧登记：v3.5.0 起各版本实测均已拦截（现象不复现），登记已更正，并补 2 条锁定测试防回归。
- `CONFIG_DRIFT`（BLOCKING 路径）行为经探针核验正常（缺注册项正确上报、终检 rc=2）；补单测需要完整部署形态夹具，仍待专门任务。
- 重复触发口径新增分析层与 CLI 回归（11 项）；G3 文案锁定（+2）；G5 变量边界与多行语义锁定（+10）。

## 升级说明

1. 下载并解压本版 ZIP；不要直接覆盖正在使用的源码目录。
2. 备份目标作用域的 settings、hooks、`behavior-policy.json` 和 `DEPLOY_MANIFEST.json`。
3. 在新包目录预演安装，显式指定原目标项目或全局作用域。
4. 无漂移或第三方冲突时，再执行 `--apply`。
5. 校验受管理部署文件与本版源码身份，随后在真实 Claude Code 会话中确认 hooks 被调用。

默认安装不覆盖已有策略文件。已有自定义策略需要对照本版默认策略；不要为了统一版本文字使用 `--force` 覆盖真实配置。

本版为 **3.5.18**：内容 = 3.5.17 及其同版内修补（含第五轮）。历史 CHANGELOG 中的「本地开发轮次」编号与软件发行号不是同一条记录。

## 验证与限制

验证对象是 Release 标签对应的确定提交，不是任意「最新一次」绿色 CI。项目测试矩阵为 Windows、macOS、Linux × Python 3.10、3.12；具体结果可从仓库 Actions 核对。

当前功能回归合计 **517 个用例**，文档检查单独计数。在线模型测试默认不启用；本地与 CI 测试不能替代用户界面和真实业务验收。

需要保留的边界：

- G3 检查证据结构，不验证内容真伪。
- G5 是已知误操作模式的补充检查，不是沙箱或安全边界。
- G7 主要处理询问与测试，不保证完整业务需求理解。
- 语义评审或状态故障时，部分保护可能失效；本版没有改为失败全阻断。
- G3 新增文案的实际引导效果需上线后观测；`CONFIG_DRIFT` 单测仍缺（行为已核验）；引用识别（real_03 形态）为已登记的 KNOWN-UNRESOLVED。
- 拦截准确率、漏拦率与真实项目中的净效率收益不因本次发行而自动成立。
