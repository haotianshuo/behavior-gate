# v3.5.19 · notes.1 后源码修补（未发布）

本次基于 `v3.5.19-notes.1`（提交 `834407d8058d9462a4aad14a4d8ea12ddf8f696c`）修补已定位的 G3/G5 问题。沿用“不随每轮开发自动加版本”的项目要求，软件版本保持 `3.5.19`，修改后的内容由 `SOURCE_IDENTITY.json` 的新快照区分。本说明不表示已发布新 Release、更新旧附件或安装到用户电脑。

## 修改范围

- **声明提取**：复用现有子句边界、否定与定语判断，避免“没有异常，上传已修复”中的真实完成声明被前半句影响。
- **分行证据**：同一事项内，明确的相邻证据字段可以关联唯一的当前声明。新事项、标题、表格、空行或归属不唯一时保持未确认，不把整份报告的观测借给每一项。
- **扫描完整性**：扫描不可用或已截断时，在成功匹配之前统一降级。证据块与行内路径使用同一判断。
- **复现分类**：显式非否定的复现声明进入既有复现检查；失败结果支持复现时保留专门分类，不并入普通成功验证事件。混合报告继续保留逐项类型。
- **heredoc 豁免**：识别引号及转义中的普通字符，只对能够确认的直接文档接收者给予正文豁免。实际命令连接、包装、替换或不确定结构保留命令检查。
- **旧自测口径**：四关自测原先依赖已取消的“可见放行”文案；改为核对独立会话中的 `stop_feedback_retry` 事件、退出码和输出协议，确保重试留下记录且不再次阻断或追加模型上下文。

## 仍保留的边界

- 自然语言的事项与证据归属只做有限结构判断，无法证明是同一个业务对象。
- 同一句多个成功声明或多个观测的完整覆盖仍未实现；字面匹配不能推广为整个系统通过。
- G5 不是完整 shell 解释器或安全边界；复杂结构可能保守地不予文档豁免。
- Bash 写入识别仍受已支持的命令形态限制；三态写入不等于能够识别任意脚本的全部副作用。
- 历史描述过滤、SQL 混合指令与 G7 复合条件等既有边界不在这次修补范围内。
